## 上海 BGP 美国 IPLC 是条什么线路

IPLC 指国际私有租用线路（International Private Leased Circuit），简单说就是在公网之外租了一条点对点的专属信道。你从上海连上入口，数据进入专线直达美国出口，中间不走公共互联网，也就不存在绕路、被限速或中途质量跳水的经典公网问题。

这里最容易搞混的是 BGP 的位置。在 MKCloud 的产品体系里，**BGP 描述的是国内入口，不是出口**。官方知识库专门强调过这一点：所谓“上海 BGP 美国 IPLC”，指的是国内一侧用上海 BGP 网络收拢流量——BGP 机房同时接入多家运营商线路，电信、联通、移动的用户都能就近高质量连入，然后流量进 IPLC 专线跨太平洋，从美国 BGP 出口发往目标网站。第三方选购指南提到这个 BGP 入口基于 UCloud 的 BGP 网络。

官方给出的端内参考延迟是 **124~134ms**。这个数字是上海到美国段的线路内部延迟，物理距离摆在那里，压不下去，也基本不会突然变成 300ms。你实际访问一个美国网站的总耗时，还要加上出口到目标服务器的那一段。第三方测评（vps.dance）的说法类似：从入口算延迟，ping 多数海外 IP 显示 100 多毫秒属于正常现象，不影响使用。

和普通美国 VPS（比如 CN2 线路）的区别也在这：普通 VPS 的延迟看运气、看高峰期，波动区间可以很大；IPLC 的价值不在“绝对延迟更低”，而在稳。对需要固定登录环境的美区店铺后台、长期运行的 API 调用这类业务，稳定比偶尔的低价重要得多。

## MKCloud 沪美专线的产品形态

MKCloud 是 2023 年成立的国人商家，主营专线 VPS，产品线覆盖广港 IEPL、沪港 IPLC、沪日 IPLC、沪美 IPLC 和 IX 类线路。沪美方向按官方知识库的分类有四种接入：沪美专线（共享，电信或 BGP 入口可选）、沪美专线（独享，上海电信入口）、沪美 BGP 专线（独享，上海 BGP 入口）和沪美 IX 专线（经云网络接入）。

交付形态是 VPS。每台机器分配 2 个独立 IPv4：1 个入口 IP 加 1 个出口 IP。你用 SSH 或 RDP 连入口，在机器里运行业务程序，程序对外发起的访问自动从美国出口 IP 发出。听到“专线”别误会成把公司办公室和美国机房拉了根管子，它不是那种裸专线服务。

有几个限制下单前必须知道，官方知识库写得很明确：

- **出口 IP 不支持外部连入**。不能用它架公开网站、收支付回调、收邮件，也不能当游戏服务端。它只适合“你主动去访问美国服务”的场景。
- 直连款绑定一个连入省份，入口只允许该省份的 IP 连接，绑定省份可以自行切换。
- 计量型套餐按上行加下行的双向流量统计，用完暂停，可以买流量重置或补差价升级。
- 默认无 SLA 保证，不提供快照和备份。

这些限制决定了它是个细分工具，不是万能服务器。适合的场景包括美区店铺后台和运营、海外办公与授权 API 访问、从 VPS 发起的素材上传和文件同步、面向美国服务的客户端测试。TikTok 运营是第三方文章提得最多的用法。

## 常见问题

**上海 BGP 入口和上海电信入口怎么选？**
官方知识库的回答很实在：不一定谁更好，从你实际用的宽带和所在省份测试。简单经验是本地网络属于非电信运营商、或团队分布多地时，BGP 入口的多线兼容性更占优；电信宽带用户走电信入口通常没问题。

**124~134ms 是我访问美国网站的总延迟吗？**
不是。这是上海到美国段的端内参考延迟，完整耗时还要加上美国出口到目标网站的路径，以及你本地到上海入口的一段。评估业务体验时按分段估算，别拿端内值当全程 RTT。

**出口 IP 可以拿来做网站或收支付回调吗？**
不可以。官方明确出口不支持外部连入，公开网站、支付回调、邮件接收、游戏服务端都不在适用范围内。这是和常规美国 VPS 最大的用法差异。

**担心商家跑路怎么办？**
没法替任何商家担保，但可以把试错成本压低：先选流量款最低档或 500GB 档月付一个月，自行测试延迟和稳定性，符合预期再考虑长周期或高配套餐。退款政策仅限质量问题，长周期订单下单前想清楚。
